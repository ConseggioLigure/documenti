# Historical document facsimiles

This repository publishes prepared historical Ligurian dictionary pages and excerpts from Casaccia (1876), Olivieri (1851), Frisoni (1910), Paganini (1857), PFB (1873) and Penzig (1897). The complete local build includes every exported entry and retained page for cataloged works with prepared scans; the public pilot is a fixed ten-entry example.

Run `python3 build.py` for the pilot or `python3 build.py --all` for every dictionary listed in both `../LigurianKB/exports/manifest.json` and the complete `../LigurianScans/manifest.json`, with Pillow installed and both sibling checkouts available. Export filenames and content keys are separate catalog fields. VPL volumes remain absent until their scans are prepared. Preparation is offline and uses a bounded raster cache. Do not add a runtime server, MCP adapter, crop service or framework. Host rendering must be checked separately in Chat and Work; local pixel checks do not prove host behavior.

Multiple public exports may share one scan document only when their content keys agree; combine them before checking canonical IDs and heading/index path collisions. Penzig's two directions share `penzig-1897`. A bounded `--all --book <document>` build must validate the unselected books' complete canonical ID sets, source-location pointers, printed locators and pixel boxes against their frozen mapping hashes, retain those mappings and existing PNG paths/bytes, and record compatible current export pins in the private producer manifest. Keep the previous pinned scan manifest available when validating changed scan registrations. Do not rename preserved image paths solely because later headword spellings changed.

Use `<document>/pagine/<source-page>.png` for registered page IDs; these IDs do not necessarily represent printed pagination. Plates use `tavola-<number>.png`, taking the first table number for shared faces. Other unregistered pages use `<source-PDF-stem>-<PDF-page>.png`. Entry images use `<document>/<root-section>/<entry-id>/<image-number>.png`. Entry IDs are the NFC lowercase first headword plus its existing homograph index, defaulting to 1; append a single trailing `-` only to an uppercase headword that otherwise collides within the same section. Validate paths case-insensitively against the whole source export and URL-encode path components. Keep Paganini's thematic section separately from its root `main_dictionary` section.

Copy full prepared pages byte for byte. Crop their existing upright frames with floor/ceil bounds; never rotate, resize, smooth, threshold or clean them again. Preserve binary text as mode `1` and continuous-tone illustrations, covers and notices in their supplied grayscale or RGB mode. Save crops at 300 DPI. Verify pixel identity, bounds, output modes and source hashes. Reuse an existing PNG only after checking its complete decoded pixels, mode, dimensions and DPI; keep its exact bytes when valid.

Number the entry's complete primary regions first in source order, then append distinct nested sense, errata and illustration crops. Preserve printed locators and the association of each original source-location pointer with its image numbers. The public `pilot.json` contains only the fixed pilot. Full producer mappings belong in ignored `exports/<document>.images.jsonl`; their opaque `source_id` joins the pinned upstream export and must not become a public identifier. `exports/manifest.json` pins the export catalog, source snapshots and mapping hashes; consumers must reject incomplete builds. Paganini’s illustration catalog keeps its private `dictionary_sha256` provenance and separately pins the public export in `public_dictionary_sha256`; preserve all bindings, objects, regions and source reviews. Keep canonical transcriptions and geometry in LigurianKB unchanged.

The prepared document folders contain generated PNGs. A full successful build removes obsolete PNGs there only after every book's output validates; a bounded build cleans only the selected document folders. Preserve all other files and never clean unrelated folders. Publish the full image collection through GitHub raw URLs; it exceeds GitHub Pages' 1 GB site limit. A local build does not establish that new image URLs are published.

Publish only when requested. Each publication must be a fresh single root commit, force-pushed to `main`; never accumulate image revisions in the published history. Force-pushing does not guarantee immediate removal of unreachable GitHub objects. Do not change hosting or upload elsewhere without authorization. Do not add license claims unsupported by the supplied sources.

Never use hard newline wraps in Markdown. Keep each paragraph and list item on one physical line.
